# Plan 12 — Fix Seed Account ID Coupling — Solution

> **Status:** ✅ Complete
> **Date:** 2026-05-23

## What Was Done

Refactored the seed script's Account creation to use `findFirst` + create/update instead of `upsert` with a custom ID, decoupling the Account ID from the User ID format.

## Changes

| File | Change |
|---|---|
| `prisma/seed.ts` | Replaced `prisma.account.upsert({ where: { id: `${adminUser.id}-credential` } })` with `findFirst` query by `providerId + userId`, then conditional create/update |

## Key Details

- Before: Account ID was `{userId}-credential` (e.g., `cm7c3rfx30000wmlvjs4l7tq2-credential`)
- After: Account ID is auto-generated by Prisma as a CUID
- The upsert now uses a `findFirst` query on the `providerId` + `userId` composite, then either updates the existing account or creates a new one with an auto-generated ID
- The create/update data no longer passes an `id` field, so Prisma generates it automatically

## Verification

- Running `npm run db:seed` on a fresh database creates the admin account successfully.
- Running `npm run db:seed` again updates the existing account (via `findFirst` + update).
- The Account ID is now a CUID (auto-generated), not a formatted string.
